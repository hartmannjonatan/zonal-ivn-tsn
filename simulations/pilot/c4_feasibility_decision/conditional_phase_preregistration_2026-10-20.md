# Conditional phase preregistration — fixed D3 verification

Created before any seed-43/47 or low-load verification result. This addendum applies only to the exploratory C4 feasibility pilot. `exploratory=true`; `official_c4_frozen=false`.

## Selection from the L2/A1 seed-41 set

The fixed rule in `protocol.md` is applied to the completed L2/A1 seed-41 records. D1 is ineligible because its TAS arm failed application deadlines (four F08 and seven F09 misses). D2 and D3 passed the technical, application, stability, sampled-clock, and drop gates in both TAS and noTAS arms. Both have recorded natural backlog episodes at CSW/TC4 and Z3/TC4, with recovery evidence; the local Z3 result is not treated as proof of recovering an arbitrary 53-frame backlog.

The preregistered objective is the sum, over changed CBS queues, of `(candidate idleSlope - C3 idleSlope) / physical egress rate`. It includes the local F13 recovery queue Z3.ZSW.eth[7]/TC4, which changes by the same +0.552 Mb/s in both candidates. Using the effective profiles and 1 Gb/s backbone / 100 Mb/s Z3 access rate:

| Candidate | Four gated TC4 egress increment | F13 local increment | Total normalized increment | Seed-41 decision |
|---|---:|---:|---:|---|
| D1 | 0.525502437 | 0.005520000 | 0.531022437 | Reject: application gate failed |
| D2 | 1.107566179 | 0.005520000 | 1.113086179 | Eligible, higher cost |
| D3 | 1.045573563 | 0.005520000 | **1.051093563** | **Select** |

Values are fractions of each physical port rate, summed across the changed egress queues; they are not a percentage of total network capacity. D3 is selected by the preregistered minimum-cost rule among the candidates that passed all required seed-41 gates. This is a pilot selection, not a claim of global optimality.

## Fixed conditional runs

Run D3 without retuning, with its exact L2 profile and GCL, alongside its same-profile noTAS control and the official C3_sync control:

1. L2/A1 seeds 43 and 47: `D3_TAS`, `D3_noTAS`, `C3_sync_control` per seed.
2. Only if all three treatments pass the applicable technical, application, stability, sampled-synchronization, and loss gates in both additional seeds, run the same three treatments at L0/A0 and L1/A1, seed 41.

The L0/L1 profiles are generated by the already frozen `profile_for` rule: derive each gated TC4 reserve from that load's C3 profile using the fixed D3/C3-L2 ratio; apply 1.02 only to Z3.ZSW.eth[7]/TC4; do not scale transient traffic into permanent reservations. D3 GCL periods, durations, and relative offsets remain unchanged. No parameters are retuned after any conditional result.

Each cell/seed uses its already frozen F21/F22 calendar; paired treatments must match the recorded calendar signature and offered populations. Simulations run serially with one OMNeT++ process, a 40 GiB free-disk floor and 7 GiB MemAvailable floor. Stop before the next run if a floor is not met. Do not rerun a completed treatment. One technical replacement per failed logical run remains the maximum; performance failure is not a technical failure.

## Gates and stop rules

Before starting the next seed, all three D3/noTAS/C3 treatments for the current seed must have valid CBS/GCL/runtime contracts, exact calendar pairing, no confirmed queue overflow losses, P1 application acceptance, queue-stability acceptance, and sampled clock offsets within 1 µs. Continuous synchronization remains unverified. The D3 TAS arm must also show no deadline misses for the hard brake flows. If any check fails, stop conditional expansion; preserve and report the failure without retuning.

Low-load extrapolation is conditional on passing both seeds 43 and 47. Any C3_sync failure is reported as a control limitation and prevents attributing the same failure to TAS. Total methodological budget remains the original maximum of 20 treatments: eight initial seed-41 treatments (including reused B and C3), six seed checks, and six low-load treatments. No new candidate or artificial-backlog run is included in this phase.
